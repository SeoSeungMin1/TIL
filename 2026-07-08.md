## 배운 내용

- State
    - 컴포넌트가 스스로 기억하고 관리하는 내부 데이터
    - 렌더링이 여러 번 일어나도 값을 유지하는 데이터
    - 값이 변경되면 React가 화면을 다시 계산하도록 만드는 데이터
    - 필요 이유
        - 변경하는 값을 관리하기 위해
            
            → 사용자 행동이나 시간에 따라 계속 변하는 값을 State로 관리
            
        - 화면을 자동으로 갱신하기 위해
            
            ```jsx
            const [count, setCount] = useState(0);
            
            setCount(count + 1);
            ```
            
            → State 변경 요청
            
            → React가 다시 렌더링
            
            → 화면 자동 갱신
            
    - useState
        - 기본 형태
            
            ```jsx
            const [state, setState] = useState(initialValue);
            ```
            
            → state : 현재값
            
            → setState : 값 변경 요청 함수
            
            → initialValue : 초기값
            
    - 기본 예제
        
        ```jsx
        function Counter() {
          const [count, setCount] = useState(0);
        
          return (
            <button
              onClick={() =>
                setCount(count + 1)
              }
            >
              {count}
            </button>
          );
        }
        ```
        
        - 동작 : 버튼 클릭 → setCount 호출 → React가 상태 저장 → 컴포넌트 재실행 → 새 JSX 생성 → 화면 갱신
    - 일반 변수와 차이
        - React가 변경 사실 모름
        - 렌더링되면 다시 초기화
        - 일반 변수는 렌더링 사이의 값을 기억하지 못한다.
    - State 저장 위치
        - 컴포넌트가 다시 실행되어도 State는 React 내부(Fiber)에 저장되서 유지
    - Boolean State
        
        ```jsx
        const [open, setOpen] = useState(false);
        
        setOpen(!open);
        ```
        
        → 켜짐/꺼짐, 모달 열기/닫기, 다크모드 토글 등 사용
        
    - 배열 State
        
        ```jsx
        setTodos([...todos, newTodo]);
        ```
        
        → 기존 배열을 수정하지 않고 새로운 배열을 만들어 전달한다.
        
    - 이전 값 필요할 때
        
        ```jsx
        setCount(prev => prev + 1);
        ```
        
        → prev : 이전 State 값
        
        → React가 자동으로 넣어준다.
        
        → 이전 값을 기준으로 계산할 때 사용
        
        사용 이유
        
        ```jsx
        setCount(count + 1);
        setCount(count + 1);
        
        // 결과 1
        ```
        
        → count = 0 → 0 + 1 요청 , 0 + 1 요청
        
        → 둘 다 같은 값을 사용하기 때문
        
        ```jsx
        setCount(prev => prev + 1);
        setCount(prev => prev + 1);
        
        // 결과 2
        ```
        
        → 순서대로 누적된다.
        
    - State는 비동기적으로 처리
        
        ```jsx
        function Counter() {
          const [count, setCount] = useState(0);
        
          const handleClick = () => {
            setCount(count + 1); // 변경 요청
            console.log(count);  // 아직 0
          };
        
          return <button onClick={handleClick}>{count}</button>;
        }
        ```
        
        → setState() 즉, 위에 코드에서 setCount()는 즉시 실행되는 게 아니라 이벤트 핸들러가 끝난 후 React가 모아둔 변경 사항을 처리하면서 재렌더링.
        
    - 배치 업데이트
        
        ```jsx
        setCount(...)
        setCount(...)
        setCount(...)
        ```
        
        → 불필요한 렌더링 감소 , 성능 향상
        
    - 불변성
        - 기존값을 직접 수정하지 않는다.
        - 잘못된 예시
            
            ```jsx
            todos.push(newTodo);
            setTodos(todos);
            ```
            
            → 기존 배열 직접 수정
            
            → React가 변경을 제대로 감지하지 못할 수 있음.
            
        - 올바른 예시
            
            ```jsx
            setTodos([...todos,newTodo]);
            ```
            
            → 새로운 배열 생성
            
            → React가 변경을 감지 기능
            
    - State는 최소한으로 관리
        - 나쁜 예
            
            ```jsx
            const [filtered,setFiltered] =useState([]);
            ```
            
        - 좋은 예
            
            ```jsx
            const filtered = items.filter(...);
            ```
            
            → 다른 값으로 계산 가능한 값은 State로 만들지 않는다.
            
            → 이런 값을 파생값이라 함
            
    - State와 렌더링
        - State 변경 → 렌더링 → 새 UI 계산
- Life Cycle
    - 컴포넌트가 생성되고 변경되고 제거되는 전체 과정
    - 컴포넌트가 화면에 나타나서 사라질 때까지의 생명주기
    - Life Cycle 3단계
        - Mount - 컴포넌트가 처음 화면에 나타남
        - Update - State 또는 Props 변경으로 다시 렌더링
        - Unmount - 컴포넌트가 화면에서 제거됨
    - Mount
        - 컴포넌트가 처음 화면에 등장하는 시점
        - JSX가 실제 화면에 표시됨
        - State 초기값이 설정됨
        - 주요 작업
            - 서버 데이터 조회
            - 초기 설정
            - 이벤트 등록
            - 외부 라이브러리 초기화
        
        ```jsx
        useEffect(() => {
          fetch("/api/users")
            .then(res => res.json())
            .then(data => setUsers(data));
        }, []);
        ```
        
        → 컴포넌트가 처음 나타날 때 한 번만 실행
        
        → 초기 데이터 조회에 많이 사용
        
    - Update
        - 이미 화면에 있는 컴포넌트가 재렌더링되는 시점
        - 발생 조건
            1. State 변경
            2. Props  변경
        
        ```jsx
        setCount(count + 1);
        
        // State 변경 -> 재렌더링 -> Update
        ```
        
        ```jsx
        useEffect(() => {
          document.title = `${seconds}초`;
        }, [seconds]);
        ```
        
        → seconds가 변경될 때마다 실행
        
        → useEffect() : 특정 값과 함께 동작하는 코드 작성 
        
    - Unmount
        - 컴포넌트가 화면에서 제거되는 시점
        - 페이지 이동, 조건부 렌더링 종료 등으로 발생
        - 주요 작업
            - 타이머 제거
            - 이벤트 리스너 제거
            - 소켓 연결 종료
            - 메모리 정리
        
        ```jsx
        useEffect(() => {
          const id = setInterval(() => {
            console.log("동작 중");
          }, 1000);
        
          return () => clearInterval(id);
        }, []);
        ```
        
        → return 안의 함수가 정리 함수
        
        → Unmount 시 실행
        
    - useEffect
        - 렌더링과 별개로 특정 시점에 코드를 실행하기 위한 Hook
        - 라이프사이클을 다루는 대표적인 도구
        - 기본 형식
        
        ```jsx
        useEffect(
          실행할코드,
          의존성배열
        );
        ```
        
    - 의존성 배열에 따른 실행 시점
        - 배열 없음
            
            ```jsx
            useEffect(() => {
              console.log("실행");
            });
            ```
            
            → Mount + 모든 Update 때 실행
            
        - 빈 배열
            
            ```jsx
            useEffect(() => {
              console.log("실행");
            }, []);
            ```
            
            → Mount 시 한 번만 실행
            
        - 특정 값 지정
            
            ```jsx
            useEffect(() => {
              console.log("실행");
            }, [count]);
            ```
            
            → Mount 시 실행
            
            → 이후 count가 바뀔 때마다 실행
            
    - useEffect와 LifeCycle
        
        
        | Life Cycle | useEffect |
        | --- | --- |
        | Mount | `useEffect(() => {}, [])` |
        | Update | `useEffect(() => {}, [value])` |
        | Unmount | `return () => {}` |
    - LifeCycle 알아야되는 이유
        - 데이터를 언제 불러올지 결정
        - 값 변경 시 어떤 작업을 할지 결정
        - 타이머, 이벤트, 소켓 등을 정리
        - 메모리 누수 방지
- Hooks
    - React에서 함수형 컴포넌트가 React 기능을 사용할 수 있게 해주는 특별한 함수
    - 상태(State), 라이프사이클(Effect), 컨텍스트(Context) 등에 접근할 수 있도록 연결해주는 장치
    - 대부분 `use`로 시작
    - useState(), useEffect()
    - 사용 이유
        - 상태 관리 가능
        - 라이프사이클 처리 가능
        - 로직 재사용 가능 (커스텀 훅)
        - 가독성 및 유지보수성 향상
    - 동작 방식
        - React는 컴포넌트가 렌더링될 때마다 함수를 다시 실행한다.
        - 그런데 State가 유지되는 이유는 React가 Hook을 호출 순서대로 저장하기 때문이다.
    - Hook 규칙
        - Hook은 함수 최상단에서 호출한다.
        - Hook은 항상 같은 순서로 호출한다.
        - 잘못된 예시
            
            ```jsx
            if (count > 0) {
              useState("");
            }
            ```
            
            → 렌더링마다 Hook 순서가 바뀔 수 있어 에러 발생
            
    - useEffect
        - 렌더링 이후에 실행되는 부가 작업(API 호출, 타이머, 이벤트 등록 등)을 처리하기 위한 Hook
        - 실행 시점
            
            ```jsx
            const [count, setCount] = useState(0);
            
            useEffect(() => {
              console.log("현재 count:", count);
            }, [count]);
            ```
            
            ```jsx
            // 버튼을 눌러서 실행
            
            setCount(1);
            ```
            
            1. count가 1로 변경
            2. 컴포넌트 다시 실행(렌더링)
            3. 새로운 JSX 생성
            4. 실제 화면을 1로 변경
            5. 그 다음에 useEffect 실행
            
            → useEffect는 화면이 그려진 후 실행된다.
